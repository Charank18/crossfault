Know the blast radius before you merge.

Faultline reads your repositories, maps which services actually call each API, and when a contract changes it shows what breaks — the calling services, the fields that stop matching, and a guard test that fails the pull request responsible.

How it works

  1. Point it at your org. Faultline indexes the repositories and resolves imports, clients and type definitions.
  2. Make a change. Open a pull request that alters a request or response contract.
  3. Read the verdict. The blast radius, the owners to page, and the failing guard test arrive on the PR itself.
faultline diff api/orders.ts          # contract changed
  affects 6 services across 3 repositories
  breaks  orders-gateway, billing-worker
  fields  order.total: number -> string
  guard   orders-gateway/test/contract.spec.ts  FAILS
